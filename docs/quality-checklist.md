# Release and evidence checklist

This checklist separates engineering checks from real-world evidence that must be collected by the project owner.

## Engineering checks

- [ ] Install requirements in a fresh virtual environment.
- [ ] Start the API and confirm GET /health.
- [ ] Start Streamlit and confirm the dashboard loads.
- [ ] Create a clearly labelled test food listing.
- [ ] Create a test recipient and enter an operator-estimated distance.
- [ ] Request matches and inspect score reasons.
- [ ] Move a test listing through allowed statuses.
- [ ] Confirm status history is recorded.
- [ ] Confirm impact totals count only delivered records.
- [ ] Run pytest -q.
- [ ] Capture genuine screenshots of the running app.

## Primary evidence — owner must complete

- [ ] Visit a real food source for the required observation period.
- [ ] Record actual place, date, start/end time and observation method.
- [ ] Take the required timestamped photographs with permission.
- [ ] Speak to a real person and accurately note their statements with consent.
- [ ] Record at least 20 genuine observations; use not recorded for unavailable values.
- [ ] Keep measured values, estimates and unknowns distinguishable.
- [ ] Write the personal reflection independently.
- [ ] Export actual AI conversations if the assignment requires chat exports.
- [ ] Record the real three-minute walkthrough and add its link.

Do not tick primary-evidence items using generated examples, reconstructed conversations, illustrations or assumptions.
